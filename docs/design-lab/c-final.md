# 홈 리뉴얼 설계 — 시안 C 실제 적용

> 총괄 / 2026-10-08. 홈 리뉴얼의 설계 원본이다. 작업 지시는 "c-final §N 기준"으로 낸다.
> C의 원본 코드: `src/app/design-lab/c/**`(읽기 전용, 수정 금지). 공통 품질 기준: `brief.md` 3절.

## 0. 확정 결정 (2026-10-08 사용자)

- 시안 중 **C 「살아있는 지도」** 로 확정. **실제 홈(`/`)에 적용**한다. 시안 페이지(`/design-lab/**`)는 더 손대지 않는다.
- 히어로만 C와 다르게 만든다. **스크롤 연동 연출은 폐기**한다(330vh 고정 트랙 → 플라이스루 스크럽 → 정착 → 핀 등장).
  - 이유: 재미있지만, 자주 방문하는 정보 사이트라 매번 스크롤 연출을 거치면 피곤하다.
- 새 히어로 구성: **첫 화면 = 서울 섬 착지 장면 + 핀 지도**. 지도(섬·건물·카메라)는 고정, 탈것과 환경 요소만 움직인다.
- 히어로 움직임은 **영상이 아니라 정지 그림 + 코드로 움직이는 요소**로 만든다(§3). 히어로 영역은 큰 화면에서 최대 폭을 둔다(§2).
  - 폐기: 히어로 영상(젠스파크 MiniMax H3). 1차 생성(768p, 704크레딧) 결과 사용자 판단 — 화질이 떨어지고 QHD 이상에서 뭉개짐, 중간에 모션이 깨지는 영역, 비행기가 건물로 들어감(그림에 들어갈 곳이 없음), 길에서 버스 1대가 2대로 분열.
  - 폐기: "착륙 1회 재생 후 정지" — 사용자: 착륙 반복은 피곤하지 않다, 사람이 그 화면만 보는 게 아니다.
- 탈것 등 움직이는 요소가 마우스 드래그 등으로 선택되지 않게 한다(사용자).
- 히어로 이후 섹션은 C 그대로.
- 일정: 오늘 홈 리뉴얼 전체를 끝낸다.

## 2. 히어로 사양

- **높이**: 한 화면(`h-content`). 고정 트랙·스크롤 스크럽 없음.
- **영역**:
  - 그림 상자 최대 폭 = 기준 그림 원본 폭(1672px). 그보다 넓은 화면은 좌우를 하늘 그라디언트로 채우고, 그림 가장자리가 하늘로 자연스럽게 이어지게 한다(경계가 보이지 않게).
  - 16:9보다 좁은 가로 화면(태블릿 가로 4:3 등)은 섬 전체가 들어오게 맞춘다(지금 코드는 좌우가 잘려 왼쪽 끝 핀이 화면 밖으로 나감).
  - 세로 화면은 9:16 모바일 그림.
- **레이어**(아래→위): 하늘 그라디언트 → 기준 그림(LCP, priority) → 움직임 레이어(§3) → 핀·장소 칩·지도 안내 → 카피(eyebrow·H1·lead·CTA) → 움직임 일시정지/재생 버튼 → 낮/밤 토글.
- **핀**: 페이지가 뜨면 바로 누를 수 있다. 등장은 짧은 CSS 순차 등장(전체 0.6초 이내). 좌표는 C `content.js`의 `places` 그대로(기준 그림은 고친 영역만 합성해 핀 좌표가 맞음). 핀 카드·장소 칩·모바일 시트·Esc 닫기·마우스/자이로 미세 틸트는 C 그대로.
- **로딩**: 첫 페인트는 기준 그림. 움직임용 그림은 첫 화면 이후 받는다.
- **카피 배치**: 건물·핀을 가리지 않는다. 데스크톱은 좌하단 유리 패널, 모바일은 하단 구름 영역이 출발점. 1440×900·390×844 실제 화면에서 확인해 위치를 정한다. H1·lead는 JS 없이 첫 페인트에 보인다.
- **낮/밤**: 라이트 = 낮 그림, 다크 = 밤 그림. 밤 에셋은 다크 테마를 실제로 쓸 때만 받는다(C와 동일).
- 문구는 기존 홈 문구 그대로(`home-data.js`). C에서 새로 쓴 몽골어 문구는 원어민 검수 필요로 남는다.

## 3. 히어로 움직임 사양 (정지 그림 + 코드 움직임)

- 그림은 전부 **Codex 래스터 그림**, 코드는 움직임만 맡는다. 모든 움직임은 은은하게 — 핀과 건물이 잘 보여야 한다.

### 3-1. 기준 그림

- 착지 이미지(k1-end / m1-end, 밤은 *-night)에서 비행기·버스를 지우고, 활주로 끝에 **문이 열린 격납고**, 정류장 양옆 도로에 **지하차도 입구 2곳**을 그린 판. 고친 영역만 Codex로 고쳐 원본에 합성한다(나머지 픽셀 동일 → 핀 좌표 유지).
- 4장: 낮·밤 × 데스크톱(16:9)·모바일(9:16). 데스크톱 낮은 완성: `home/v1/hero-base-day-v2.webp`(웹), `home/originals/hero-base-day-v2.png`(원본).

### 3-2. 움직임 요소

| 요소 | 그림 | 움직임 |
|---|---|---|
| 비행기 1대 | 투명 배경 스프라이트(하강 자세 1장 + 활주 자세), 그림자 | 좌상단 화면 밖 → **방향 고정(회전 없음)으로 금빛 항로 선을 벗어나지 않고 따라 하강** → 선 끝(활주로 끝) 착지 → 중앙선(흰 점선) 위로 감속(**도착 지점에서 흰 실선 위 도로로 벗어나 보이지 않게**) → 활주로 위 정차(약 6초) → 부드럽게 사라짐 → 다음 비행기 (2026-10-08 사용자) |
| 버스 1대 | 투명 배경 스프라이트(직진 방향 1자세), 그림자 | 지도 앞쪽 끝에서 나타나 **회전 없이 직진** → 오른쪽 지하차도(지하철 유리 지붕 오른쪽 위, 연못 위쪽 입구)로 들어가 사라짐. 연못 정원 구간에서는 기준 그림의 나무가 버스를 가림. 주행 9초, 16초마다 (2026-10-08 사용자) |
| 구름 흐름 | 투명 배경 구름 띠(끝이 이어지는 그림) 2겹 | 섬 뒤(먼 층)·섬 밑면 앞(가까운 층)에서 서로 다른 속도로 천천히 옆으로 흐름 |
| 구름 그림자 | 효과 레이어 | 옅은 그림자가 섬 위를 천천히 지나감 |
| 굴뚝 연기 | 연기 덩어리 그림 | 피어오르며 커지고 옅어짐, 시차를 두고 반복 |
| 불빛 | 효과 레이어 / 밤 기준 그림에서 잘라 낸 창문 영역 | 낮: 구급차 경광등·관제탑·편의점 불빛이 은은하게 깜빡임. 밤: 창문 일부가 켜졌다 꺼짐 |
| 연못 빛 반사 | 연못 모양으로 가린 효과 레이어 | 수면 위로 빛 반사가 천천히 지나감 |

- 나무 흔들림은 하지 않는다(손 대비 효과가 작음).
- **탈것 그림은 회전하지 않는다(방향 고정, 2026-10-08 사용자)** — 비행기는 하강 자세 그림 1장 그대로 금빛 항로 선을 따라 내려오고, 버스는 머리 방향으로 직진한다.
  - 폐기(1차 움직임, 사용자 확인): 비행기가 격납고로 들어감 — 격납고가 활주로·도로와 떨어져 있음. 버스·비행기가 옆으로 이동함.
  - 폐기(2차, 사용자 확인): 비행기가 금빛 항로를 따라 내려오며 옆으로 미끄러짐(선 각도에 맞는 자세 그림이 없었음).
  - 폐기(3차): 금빛 항로 대신 활주로 방향 직선 진입 — 사용자가 고르지 않았는데 총괄이 혼자 정함. 사용자: 비행기가 선을 이탈하면 안 된다.
  - 폐기(4차, 사용자 확인): 비행기 그림을 선 진행 방향으로 회전(선 끝에서 약 70°)·선 각도별 하강 자세 그림 — 머리를 박는 추락처럼 보임. 사용자: 비행기 방향 고정.
  - 폐기(4~5차, 사용자 확인): 착지 지점·활주 경로 전체를 새로 잡음(활주로 경계 기준, 몸통 기준) — 지적받지 않은 착지까지 바뀌고 옆 도로로 넘어감. 사용자: 지적한 마지막 도착 부분만 고친다(이전 값에서 살짝).
- **들어가 사라지는 표현**: 지하차도 입구 벽·연못 정원 나무를 기준 그림에서 잘라 탈것 위에 겹친다(앞가림 레이어).
- **주기**: 비행기 약 20초마다 1회, 버스 16초마다 1회.
- **좌표**: 경로·위치·크기는 모두 그림 상자 기준 %(핀과 같은 기준). 데스크톱·모바일 각각 따로.
- 모바일 그림은 더 위에서 내려다본 구도라 탈것 그림을 모바일용으로 따로 그릴 수 있다(각도 확인 후 결정). 밤에는 탈것도 밤 버전(창문 불빛·항공등).

### 3-3. 상호작용·접근성·성능

- 움직임 레이어 전부: 마우스·터치 이벤트 받지 않음(`pointer-events: none`), 선택·끌기 금지(`user-select: none`, `draggable={false}`), 길게 누름 메뉴 금지(`-webkit-touch-callout: none`). 클릭은 핀·칩·버튼만.
- `prefers-reduced-motion`·`saveData`: 전부 정지(기준 그림만).
- 히어로가 화면 밖이거나 탭이 숨겨지면 멈춘다. 일시정지/재생 버튼(WCAG 2.2.2).
- 움직임은 transform·opacity 위주. 무거운 필터는 쓰지 않는다.

### 3-4. 순서

- **데스크톱 낮 1개 먼저**(위 움직임 전부 포함) → 사용자가 실제 홈 화면에서 확인 → 밤·모바일.

## 4. 코드 구성

- `src/app/page.jsx`(서버, SSG): `metadata`(canonical·OG 유지) + `WebSiteJsonLd` + 새 홈.
- 컴포넌트: `src/components/home/`에 C 코드를 옮겨 쓴다(design-lab 폴더를 import하지 않음). 데이터: `src/data/home.js`(home-data + C content 중 필요한 것).
- 300줄 넘는 파일은 분리. 색은 C 토큰(CSS 변수) 그대로.
- 기존 `HomeContent.jsx`·`HomeContent.module.css`는 새 홈이 완성되면 쓰지 않게 된다 → 삭제는 사용자 승인 후 총괄이 한 번에.

## 5. 에셋

- 운영 홈 에셋은 R2 **`home/v1/`** 에 둔다(시안 폴더를 나중에 정리해도 홈이 깨지지 않게). C에서 쓰는 이미지·루프 영상은 `design-lab/v1/c/`에서 복사 완료. 히어로 기준 그림·움직임용 그림도 여기에(같은 경로 덮어쓰기 금지, 고치면 새 이름).

## 6. 완료 기준

- `/`가 §1 순서로 보이고 모든 링크가 실제 페이지로 동작.
- 첫 화면에서 스크롤 없이 핀을 누를 수 있다(데스크톱 1440×900, 모바일 390×844, 태블릿 가로 4:3에서 핀이 잘리지 않음).
- QHD(2560) 이상에서 그림이 원본보다 크게 늘어나지 않고, 가장자리 경계가 보이지 않는다.
- §3-2 움직임이 이음새 없이 반복되고, 탈것이 건물을 통과하거나 갈라지지 않는다. 움직임 요소가 드래그·선택되지 않는다.
- 일시정지 버튼 동작, 화면 밖이면 멈춤, saveData·reduced-motion에서 정지.
- 낮/밤 전환, 콘솔 에러 없음, 첫 화면 ≤ 1.5MB(실측 보고).
- design-lab 파일 변경 없음.
